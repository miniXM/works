# 重建与再打包技术说明

这份说明记录“这个包是怎么做出来的”，以后厂商更新版本、你想再打一次包时按这里的步骤做。

## 一、原软件的结构

- 客户端是 Electron：`videomix\videomix.exe` + `resources\app.asar`（74.7 MB），
  业务代码在 `dist-electron/main.js` 和 `dist\assets\*.js` 里。
- 本地后端 `resources\backend\KrLongAI.exe` 是 Python/Flask，监听 `127.0.0.1:35006`，
  `GET /activation/info/` 返回本机设备指纹，客户端把它显示在“设备激活”页上。
- 激活是 HTTP 请求：`POST {base}/rpc/authActivateCode`（激活）与
  `POST {base}/rpc/judgeActivateCode`（每 2 分钟复核），
  请求体 `{"activateCode":"...","deviceId":"...","category":2}`。
  返回 `SC` 通过；`E1` 激活码不存在、`E2` 设备不匹配或超出绑定数、`E3` 已过期、`E4` 已吊销。
- 原厂商地址：`http://101.200.3.94:8081`、`http://101.200.3.94:5005`，
  更新源 `https://static.qiniuyun.highvenue.cn/videomix/`。

## 二、改造点

1. **改激活地址**：把 app.asar 里两处厂商地址换成 `http://127.0.0.1:8081`（客户端本机代理），
   更新源换成不可达域名。脚本：`work\patch_asar_v2.py`。
2. **同步 asar 完整性哈希**：Electron 启动时会校验 `resources\app.asar`，
   期望值写在 `videomix.exe` 的 `ELECTRONASAR` 资源里（`{"file":"resources\\app.asar","alg":"SHA256","value":"..."}`）。
   app.asar 一旦改动就必须把新值写回 exe，否则启动直接 FATAL 退出。
   脚本：`work\patch_exe_integrity.py`。
   注意：校验用的哈希**不是文件的 SHA256**。取新值的办法是：先只换 asar 启动一次，
   从报错 `Integrity check failed for asar archive (期望值 vs 实际值)` 里把“实际值”记下来，
   再把它写进 exe。
3. **关闭自动更新**：`resources\app-update.yml` 的 owner/repo 改成不存在的仓库。
4. **三合一启动器** `VideoMix.exe`（C# WinForms，源码 `work\videomix-rebuild\sfx\VideoMix.cs`）：
   安装器 + 本地授权代理 + 启动器。靠文件尾 16 字节页脚
   （`int64 长度` + `"VMIXPAY1"`）区分“这是安装包”还是“已安装的启动器”。
   - 启动器在 `127.0.0.1:8081` 起代理，把激活/复核请求转发给 `license-server.json` 里配置的服务器，
     并且**在代理里验签**（见第 6 条），验不过的响应会被就地改写成 `E9`；
   - `/S` 静默安装，参数读同目录 `setup.ini`（`dir` / `server` / `desktop` / `launch`）；
   - `/uninstall` 会先结束正在运行的客户端进程，再删除快捷方式、注册表项和安装目录。
5. **授权服务器** `VideoMix-LicenseServer.exe`（源码 `work\videomix-rebuild\licenseserver\LicenseServer.cs`）：
   WinForms 界面，生成/吊销/解绑激活码，数据存同目录 `license-data.json`，
   签名私钥存同目录 `license-signing-key.xml`（首次启动自动生成）。
6. **授权签名（防假冒服务器）**：后台每次返回 `SC` 时，用 2048 位 RSA 私钥
   （PKCS#1 v1.5 + SHA-256）给 `{版本, 指纹, 激活码, 设备指纹, 签发时间, 到期时间}` 签一张票据；
   客户端用 `build-launcher.ps1` 编译进去的公钥（`Generated.LicensePublicKeyXml`）验签，
   并核对指纹与设备指纹。验签失败就改写成 `E9`，界面提示
   “授权校验未通过：签名验证失败（对方不是正版授权后台）”，细节写进 `license-client.log`。
   两侧实现分别在 `sfx\VideoMix.cs` 的 `TicketGate` 与 `server.py` / `LicenseServer.cs` 的密钥模块里，
   已用交叉签名验证过（Python 签、.NET 验，改一个字节即失败）。
7. **老系统 SQL 兼容**：后台只用 SQLite 3.7 就支持的语句。CentOS 7 自带 SQLite 3.7.17，
  而 UPSERT（`ON CONFLICT ... DO UPDATE`，要 3.24+）和 `VACUUM INTO`（要 3.27+）它都不认，
   2.1.0 在那种机器上会直接 `sqlite3.OperationalError: near "ON": syntax error`。
   现在设置写入改成 `INSERT OR REPLACE`、客户端配置计数改成先查后更新、
   每日备份改用 Python 的 `sqlite3` 在线备份 API（`conn.backup()`），
   并且后台启动时会打印 `Python x / SQLite y`，方便一眼看出运行环境。
   部署包里的 `selfcheck.py` 可以在目标服务器上把整套流程跑一遍验证（65 项）。
8. **品牌与文件名（一键换）**：品牌文字不写死在 exe / asar 里，而是由
   `work\rebrand\brand.json` 生成，改一处全套生效。管线 `work\rebrand\rebrand.py`：

   | 步骤 | 脚本 | 干什么 |
   | --- | --- | --- |
   | 2 | `make_images.py` | 生成 7 尺寸图标 / 托盘 / favicon / 横版 logo（`keepLogoImages=true` 时整步跳过，保留原版图标） |
   | 3 | `make_rules.py` + `build_asar.py` | 按规则改 app.asar 里的品牌文案，其余字节原样复制，头部 JSON 重新计算 |
   | 4 | `patch_integrity.py` + `patch_exe.py` | 把 asar 头部 JSON 的 SHA256 写回 exe 的 `ELECTRONASAR` 资源，再改 exe 的图标与 VERSIONINFO |
   | 5 | 生成 `sfx\Brand.cs` | 启动器的品牌常量（安装向导标题、快捷方式名、注册表卸载项名等 34 处文案） |
   | 6 | `build-launcher.ps1` | 编译启动器，`Generated.AssemblyInfo.cs` 给安装包 exe 写公司/产品/版权/版本属性 |
   | 7 | `build_payload.py` | 以常数内存重建 972 MB payload，只替换变化条目（含大小与 CRC 自检） |
   | 8 | `build-setup.ps1` | 拼出安装包并打印 SHA256 |

   客户端文字落点：`dist/index.html` 的 `<title>` 与启动动画、`LoginPage-*.js` 激活页标题、
   `index-*.js` 顶部品牌位与侧栏兜底名、`SystemSettingsPage-*.js`、`dist-electron/main.js`；
   图片落点：`dist/app-icon.png`、`dist/tray-icon.png`、`dist/favicon.*`、
   `dist/assets/极速-CaezdxB6.png`（方形）、`dist/assets/极速1-bJwsFj2F.png`（横版）。
   文字替换只认整串字面量（例如带反引号的 `` `极速` ``），所以不会误伤图片文件名和路由名
   （`VideoMix-BZfwcH3T.js` 这类 chunk 名保持不变）。
`check_assets_unchanged.py` 用来确认“只改文字”时图标与 logo 一个字节都没动；
`verify-brand.ps1` 会真装一遍并检查 19 项（其中包含程序与安装包的文件属性，
以及“装出来的 asar 里两条行为补丁还在不在”）；
`verify-restart.ps1` 单独验“退出再启动”这一条：清掉 Chromium 本地存储后重启，
确认仍然停在激活页、并且本机代理 `GET /vm/license` 能把激活码交出来。
9. **在线升级的自愈逻辑**：Electron 把 `resources\app.asar` 头部 JSON 的 SHA256 写在主程序
   `videomix\videomix.exe` 的资源里（`ELECTRONASAR`），对不上就 `Integrity check failed`
   秒退。而更新包默认只带启动器 + app.asar，不带那个 222 MB 的主程序，所以启动器在拉起主程序
   之前会自己算一遍并就地改掉这个哈希（`sfx\AsarIntegrity.cs`，口径与 `patch_integrity.py` 一致，
   分块扫描 + 原地写 64 字节，不整文件读进内存）。实测：装 1.0.0 → 后台发布 1.0.1（15.7 MB）
   → 客户端校验签名与 SHA256 → 落地 → 换启动器 → 同步哈希 → 重启后正常打开，
   窗口标题变成新版本的 `极速混剪 1.0.1`，后台「客户版本分布」显示 1.0.1、未升级 0 台。
10. **横版 logo 的抠底与宽高比**：客户给的两张图都是「单色图形 + 纯色底」，
    但设计稿在 `icon.png` 里把剪刀环、斜杠缝做成了镂空透明，在 `zuojiao.png` 里又带了
    `#E2E8F7` 的实心底。处理方式：
    - 横版 logo：按「像素 = 墨色 × a + 底色 × (1-a)」反解出每像素 alpha
      （三通道最小二乘，`work\rebrand\key-wordmark.py`），底色消失、边缘保留抗锯齿；
      再裁掉四周空白、按高 1027 等比导出。客户端侧栏卡片实测底色就是 `#E2E8F7`，
      和设计稿底色一致，所以抠不抠都看不出接缝，抠掉以后换底色也不会露方块。
    - 宽高比必须保留：客户端用 `max-height:52px` + `max-width:196px` 渲染，
      画布越空 logo 显得越小。原厂那张内容只占画布 2647×647，实际画出来约 139×52；
      裁紧后按 3.2 的宽高比出图，实画约 166×52，同样条件下字更大更清楚。
      `make_images.py` 早期会把横版 logo 硬 `resize` 成 2754×1027（会拉伸变形），已改成等比。
     - 方形图标：镂空补白（`fill_holes`），否则深色任务栏上会糊成一团。
11. **界面微调（侧栏 logo 留白 + 标题栏固定）**：客户对着实际界面提了两点，改法写在
    `work\rebrand\ui_rules.py`，由 `make_rules.py` 末尾并进同一条 asar 文本替换队列，
    所以换品牌时会一起进包，不用单独跑一步。
    - 侧栏顶部的 logo 图片原来撑满整个胶囊（`.app-sidebar__logo-img` 是
      `max-width:100%;max-height:52px`，而胶囊只有 68px 高，四周没有余量）。
      改成 `max-width:86%;max-height:42px`，上下各留出约 13px。
    - 顶部那条标题栏原来会跟着页面滚动上下飘。根因是**整个文档在滚**：
      `html,body,#app` 是 `height:100%`，而 `.app-layout` 只有 `min-height:100vh`，
      内容一长就把文档撑开，`.app-layout__main` 的 `overflow:auto` 因为没有确定高度而失效，
      于是 `.app-header` 的 `position:sticky` 相对文档生效，一滚就被顶到窗口最上沿。
      改法是把外层做成固定高度外壳（`.app-layout` 改 `height:100%;overflow:hidden`，
      `.app-layout__body` / `.app-layout__main-column` 补 `height:100%;overflow:hidden`），
      滚动收进 `.app-layout__main` 自己里面，标题栏回到普通流式（`position:relative;top:auto`），
      位置永远不动，内容从它下面滚过去。
    - 改动方式：直接改压缩后的 CSS 文本（`ui_rules.py` 里两条“旧串 → 新串”整串替换），
      两条旧串在 base asar 里各命中 1 次，构建时人工核对命中数（`EXPECTED_HITS`）。
     - 只改 CSS 看效果可以走 `work\rebrand\quick-asar.ps1`（约 2 秒，只重建 app.asar + 主程序，
       并把这一份同步到 `work\rebrand\shots\app` 这个临时目录里启动看效果，
       该目录不存在时脚本会自己建，随时可以删）；正式出包仍然走 `rebrand.py`。
     - 量化验证脚本：`work\rebrand\probe\layout-probe.py`（CDP 连主程序量 DOM），
       截图脚本 `work\rebrand\probe\check-ui.ps1`。
 12. **镜头空档（配音优先 + 0.5 秒口径 + 合成前提醒）**：客户反馈“镜头素材 10 秒、
     文案只有 3 秒，成片后 7 秒没人说话”。根因在客户端自己的时间轴规则里
     （`BatchGenerationPage` 的构建函数 `Bt`），不是后端：
     - 有配音 → 画面按配音时长裁，尾部只留 0.07~0.23 秒
       （当时在 `work\probe-duration\` 里解析过 6 条真实成片的 ffmpeg 日志，条条如此，
       很干净；这个临时目录 2026-09-18 已清理）；
     - 没配音 → 用「镜头剪辑」的「时长（秒）」，而这一项在开配音时是隐藏的、
       默认 0 的含义是“把整段素材播完”，于是 10 秒素材就真的播 10 秒。
     补丁在 `work\rebrand\gap_rules.py`，由 `make_rules.py` 并进同一条 asar 文本替换队列
     （四条整串替换，每条旧串在 base asar 里各命中 1 次，构建时核对 `EXPECTED_HITS`）：
     - `VmxGap = 0.5`（判定口径）、`VmxCps = 4.5`（中文口播估算语速，用的时候还要除以
       界面上的语速倍数，单个镜头下限 0.6 秒）；
     - 配音开着、镜头有文案、但这一镜没生成出配音时，画面按文案字数估算裁短，
       不再把整段素材播完；
     - 合成前扫一遍镜头，弹「合成前提醒」列出“没配音但有文案”的镜头
       （写成人话，例如“镜头 1（约 5.1 秒）”）：点“取消，我先去改”就不提交
       （任务按软件自带的取消逻辑变成“已取消”，改完点“重试合成”），点“继续合成”才提交。
     - 有个坑值得记：这个页面自己的 import 里没有 Element Plus 的 MessageBox，
       要在 `BatchGenerationPage` 那条 import 上加 `n as VmxBox`；`index-*.js` 那个路由文件里
       也有同名导出，但改它不生效（整串替换会钉死到实际用到的那个文件）。
     实测（`work\rebrand\probe\gap-run.ps1` + `gap-e2e.py`，客户端带 `--remote-debugging-port`
     起来、8081 用 `proxy8081.py` 替身）：两个镜头文案 22 字 / 16 字、素材是 10 秒级片段、
     没有 MiniMax Key 所以没配音；弹窗正文和按钮见 `截图\16`；点“继续合成”后抓到提交给
     本机合成服务的 timeline 总长 **9.533 秒**（画面 0~5.200 与 5.433~9.233，配音 0 条），
     真机成片 `ffprobe` 量出来 **9.566 秒**；改之前这两段会各播 10 秒、成片约 20 秒。
     顺手记一条测试技巧：真正的启动器 `VideoMix.exe` 会把 `--remote-debugging-port` 吞掉，
     所以自动化测试是直接起 `videomix\videomix.exe` 并旁挂一个 8081 代理替身，
     而不是走启动器。
 13. **账号档案：预置示例档案 + 「AI 帮我写」（问答生成整份档案）**：
     改之前账号档案有 15 项要填（含出生年份、性别），给的是“卖鸭血粉丝汤的红姐”
     那套空表单，客户拿到手基本不知道怎么写。现在这一页做了四件事。
     - **系统预置一份写满的示例档案**（北京烤鸭店的李逍遥：海淀人、2007 年开店、
       投了 100 多万、2012 年盲目扩张亏过 200 万……共 13 项全是具体内容，
       不再用 XX 占位），客户打开就能看到“一份能用的档案长什么样”，照着改自己的。
       数据只写在 `work\rebrand\persona_seed_rules.py` 的 `STOCK` 一处，
       `STOCK_JS` 同时注进 persona_rules 的 AI 补丁，两边永远一致。
     - **表单去掉「出生年份」「性别」两格**（这两项跟口播文案没关系），
       连「当前改写参考」也不再输出这两行。
     - **「AI 帮我写」按钮**：客户只回答 3 个问题（**你是做什么的**、**门店/品牌/账号叫什么**、
       **在哪座城市、哪个商圈**，其中“你是做什么的”必填）再选一个口吻，
       点「生成档案」就一次把整份档案写好；**剩下 10 项（别人怎么称呼你、籍贯、
       投了多少钱干了什么事、做了多少年、遇到过什么挫折怎么解决的、为什么值得信赖、
       目标或期望、目标客群、特色卖点、产品介绍和价格）全部由模型按这个行业和这座城市补全**，
       生成完仍可逐格手改；**点「新建档案」建完之后直接弹这个对话框**，不用自己再去找按钮。
     - **修了“选中输入框边框会消失”这个 bug**：根因是 Element Plus 的
       `.el-textarea__inner:focus{box-shadow:0 0 0 1px var(--el-input-focus-border-color) inset}`
       和 `.el-input__wrapper` 的描边，都依赖只在 `.el-textarea` / `.el-input` 这层父容器上
       定义的 CSS 变量；而这个对话框是挂在 `document.body` 上的浮层，拿不到那层父容器，
       变量取不到值，整条 `box-shadow` 直接失效，看起来就像边框没了。修法是在 `.vmx-ai-mask`
       下给这几类控件写一层不依赖变量的兜底描边（默认 `#dcdfe6`、hover `#c0c4cc`、
       聚焦 `var(--el-color-primary,#409eff)`），原生 `<select>` 那条也一起补了。
     - 走的是**软件自己已有的百炼通道**，不额外配一套 Key、也不经我方服务器：
       复用 `api-*.js` 里的 `t`（`dashscope:chatCompletions`）和 `n`（取正文），
       读取的是「系统设置 → 阿里云百炼 Key / 改写模型」里客户已经填好的那套配置
        （和软件自己的「AI 改写文案」同一个 Key）。没填 Key 时点开按钮就红字提示，
       并让「生成档案」拦住不提交。
     - 三处整串替换写在 `work\rebrand\persona_rules.py`（AI 对话框本身），
        五处写在 `work\rebrand\persona_seed_rules.py`（示例档案、去掉两格、
        改写参考、新建后弹窗、示例文字），每条旧串在 base asar 里
        各命中 1 次（示例文字那条命中 2 次），`EXPECTED_HITS` 由
        `work\rebrand\check-rule-hits.py` 和构建日志双重核对：
       1. 在 `AccountPage.*.js` 的 import 行后追加
          `import{t as VmxChat,n as VmxText}from"./api-D6D4R6Zx.js";`；
       2. 在「清空内容」按钮前插一个 `<el-button>`「AI 帮我写」；
       3. 在 `K=_(()=>B.buildActivePersonaText());` 这条 `let` 语句**之后**追加
          整块 `VmxAi*` helper。
     - 对话框不用 Vue 组件拼（这是压缩产物，手写 render 太容易错），
       而是在 `document.body` 上挂一个用 Element Plus 全局类名
       （`.el-input__wrapper` / `.el-textarea__inner` / `.el-button`）搭的浮层，
       事件委托，关闭就移除，所以外观和软件自己的弹窗一致。
     - 模型必须返回 13 键 JSON；`VmxAiParse` 会剥掉 ``` 围栏、截取首尾 `{}` 再解析。
        提示词分两套（`VmxAiPrompt(e,t)`）：勾了「覆盖已经填过的内容」时写的是
        “这一次是按问答重写整份档案：上面问答写的就是标准答案，现有内容作废、

   而授权票据是激活成功那一刻同步写的，比本地存储新。
   代理是在激活成功那一刻就把票据写进安装目录的，所以从代理取就不会丢也不会旧。

  所以 `vm-theme.js` 用一个 `MutationObserver` 把皮肤节点一直拎到 `<head>` 末尾。
- 主题写在 `<html data-vm-theme="light|dark">`，值存在 `localStorage['vm-theme']`；
  v2 的口径是"没有值时跟随系统"，v3 起改成**默认暗黑**，只在用户手动点过之后才以
  `localStorage` 为准——否则同一份包在不同机器上会一会儿深一会儿浅，看起来像没改。

### v4 的布局改造（"只有左边菜单变黑了"之后补的）

第一版只改颜色，用户反馈"就左侧菜单换了黑色，其它都没变化"——这是实话：客户端原本
浅色面积就很大，单换配色肉眼几乎看不出。所以 v4 补了结构层面的改造：

- `vm-theme.js` 里新增 `markChrome()`，做三件纯 CSS 做不到的事：
  1. 顶栏插面包屑 `.vm-crumb`、快速跳转 `.vm-quicknav`（带搜索框和下拉面板）、刷新按钮 `.vm-icon-btn`；
  2. 侧栏按「创作 / 发布 / 系统」插分区小标题 `.vm-nav-label`，底部插授权状态卡 `.vm-side-card`；
  3. 用 `getBoundingClientRect()` 判断侧栏是不是折起来了，给 `<html>` 打 `data-vm-nav="mini"`，
     收起时自动隐藏上面这些附加件。

### 第三个坑：顶栏的窗口拖拽区会吃掉点击

`.app-header` 是窗口拖拽区（`-webkit-app-region: drag`，用来拖动无边框窗口），
**注入进去的按钮如果不声明 `-webkit-app-region: no-drag`，真实鼠标点击会被系统当成"拖窗口"吃掉**。
CDP 里 `element.click()` 不经过命中测试，所以程序化测试照样通过，肉眼点就是"没反应"——
这就是用户反馈的"右上角主题按钮没反应"。

修法：`.vm-theme-toggle`、`.vm-icon-btn`、`.vm-quicknav`、`.vm-crumb` 都加
`-webkit-app-region: no-drag`。验证用 `work\rebrand\probe\click-real.ps1`，
它走 `SetCursorPos` + `mouse_event` 发真实鼠标事件，不是 JS 点击：

```powershell
& $pwsh -NoProfile -File work\rebrand\probe\click-real.ps1 -X 1139 -Y 34
# 点完再查 <html data-vm-theme> 和 localStorage['vm-theme'] 有没有按预期翻转
```

注意：Windows 上"唤醒未聚焦窗口"的那一次点击会被系统吃掉（所有程序都一样），
所以脚本会先 `SetForegroundWindow` 再等 900ms 才点；连续点第二次一定生效。

### 踩到的两个坑（改皮肤前值得知道）

- **新条目必须带 integrity**。往 asar 头部树里插新文件时，`size` / `offset` 之外还要写
  `integrity`（`algorithm` / `hash` / `blockSize` / `blocks`），否则开了 ASAR 完整性校验的
  Electron 直接 FATAL：`Failed to read integrity for file in ASAR archive`。
  这是 `build_asar.py` 的 `insert_entry()` 负责的。
- **客户端自己的分页 CSS 也带 `!important`，而且优先级更高**。例如
  `.workbench-actions__secondary.is-disabled { background:#f3f4f6 !important }`，
  皮肤里单写一个 `.workbench-actions__secondary` 压不住，必须写成
  `html[data-vm-theme] :is(.workbench-actions__secondary, ....is-disabled)` 才盖得住。
  同理，只扫 `background-color` 会漏掉写死的**浅色渐变**（素材中心的 `.assets-stats`），
  所以补了 `work\rebrand\probe\scan-light-css.py`，把 `linear-gradient(...)` 里的浅色一起扫出来。

### v5 里修掉的两个真 bug（都是这次改造自己带出来的）

### 按钮"时灵时不灵"的真因：`paint()` 把图标节点换掉了

先排掉一个想当然的答案。顶栏 `.app-header` 是窗口拖拽区（`-webkit-app-region: drag`），
很久以来这个项目里都记着"不声明 no-drag 就会被拖拽区吃掉点击"。这次量了一下，**不是它**：

- 新增 `probe\theme-click-test.py`：枚举窗口找到客户区原点，用真实系统鼠标事件
  （`SetCursorPos` + `mouse_event`）做"冷点击"——先把光标停在别处，再跳过去、
  几乎不停留就按下。每次都校验 `GetForegroundWindow()`，抢不到前台的那次不算数。
- 把 `.vm-theme-toggle` 临时改回 `position: static`（即"没有自己的合成层、no-drag 登记不上"的假设条件）
  之后，冷点击 **28 次全中**。所以 no-drag 一直是生效的，那条老经验在这个版本上不适用。

真正的开关在 `vm-theme.js` 的 `paint()`：它原来无条件重写按钮的 `innerHTML`。
而 `ensureToggle() → paint()` 挂在 `MutationObserver` 上，页面上任何一处 DOM 变动都会触发它
（客户端有轮询、状态刷新、提示条，变动很密）。只要这一次重写正好落在 **mousedown 和 mouseup 之间**，
按下去的那个 `<svg>` 和松开的那个就不是同一个节点了，浏览器算不出 click 的目标，
事件就此消失 —— 表现就是"有时候点得动、有时候点不动"。

`probe\click-node.js` 把节点编号打出来，丢掉的点击全都长这样（seq 不同 = 节点被换过）：

```
mousedown path seq=3  →  mouseup path seq=3  →  click   ✅
mousedown path seq=4  →  mouseup path seq=5  →  （无）  ❌
```

修法是让 `paint()` 只在主题真的变了的时候才碰 DOM：

```js
var mode = ... === 'dark' ? 'dark' : 'light';
if (btn.getAttribute('data-vm-mode') === mode) return;   // 没变就别动
btn.setAttribute('data-vm-mode', mode);
btn.innerHTML = ...;
```

修完实测：主界面 `.vm-theme-toggle` 冷点击 **15+15 次全中**（延迟 10ms / 0ms 各一轮），
激活页 `12/12`，快速跳转框 `8/8`，右上角用户胶囊 `8/8`。改之前同样是 20ms 延迟，
激活页只有 10/12、主界面 7/8。

### 默认主题改成白天，并处理老机器上的旧记录

`vm-theme.js` 里 `DEFAULT_MODE` 从 `'dark'` 改成 `'light'`。但光改这一行不够：
老机器（包括本机测试的那个）`localStorage['vm-theme']` 里已经存着上一次的 `dark`，
启动时永远读得到，用户看到的还是暗黑。

所以加了一个一次性的默认值版本号：`vm-theme-default` 里存 `DEFAULT_TAG`（现在是 `light-1`），
对不上就忽略旧记录、用新默认，并把这次实际生效的主题写回去。这样：

- 老机器升级后第一次启动 → 白天（旧记录忽略一次，并覆盖成白天，不会第二次又跳回暗黑）；
- 之后用户自己点过暗黑 → 记在 `vm-theme` 里，以后都按用户的来；
- 以后想再换默认值，把 `DEFAULT_TAG` 改个字符串即可。

实测（先把 `vm-theme` 设成 dark、`vm-theme-default` 删掉，模拟老机器）：
第一次启动 `theme=light stored=light`，第二次启动仍 `theme=light`。

### 9.2 缩略图：客户端那个格子是空的，得自己补

`.workbench-task__thumb` 在客户端里是 `S('div',{class:'workbench-task__thumb',"aria-hidden":'true'},null,-1)`
—— 一个**没有子节点的空 div**，56×56，只有一层写死的渐变背景。源码里
`thumbnail` / `previewImage` / `cover` 这些字段一个都没有，所以"换成预览图"只能自己算。

素材其实都在，链路是这样（`vm-theme.js` 里新增的 `markTaskThumbs()`）：

1. 任务数据从 Pinia 的 `mix` store 读：
   `document.getElementById('app').__vue_app__.config.globalProperties.$pinia._s.get('mix')`。
   组件本身就是拿 `tasks` 按 `createdAt` 倒序取前 5 条，这里照抄同一套规则，所以按下标能一一对上 DOM 里的 `<li>`。
2. 每条任务第一个镜头的 `shots[0].folder` 是素材目录，
   `selectionIndices[0]`（没有就用 `shots[0].selectedFileIndex`）是选中了目录里的第几个文件。
3. 文件列表走客户端自己的 IPC `window.electronAPI.listSupportedVideosInFolder(folder,{probeHdr:false})`
   —— 就是素材中心用的那个接口，返回 `[{path,name}]`。
4. 抽帧和素材中心的 `VideoFirstFrameThumb` 组件一模一样：`pathToFileUrl()` → 藏一个 `<video>` →
   `loadedmetadata` 后 seek 到 `min(0.1, duration*0.02)` → `onseeked` 里画到 canvas → `toDataURL('image/jpeg',0.8)`。
   皮肤侧只负责把它塞进 `.workbench-task__thumb` 的 `background-image`（配 `background-size:cover`）。

抽一帧要解一次码，所以是**串行队列**（`pumpThumbs()`），结果按 `文件夹 + 序号` 缓存，
页面切走再切回来不重新解码。任何一步失败就保持客户端原来的渐变占位，不会留破图。
`data-vm-thumb` 记的是"这一格现在是哪条任务"，Vue 复用 `<li>` 时也能正确换图。

### 9.3 "卸载不掉"的真因：不是卸载器坏了，是旧版还在

先把结论摆出来，免得继续往错的方向改：**我们这版的卸载路径本身是通的。**
实测 `VideoMix.exe /uninstall /S` 退出码 0，安装目录、HKCU 卸载表项、桌面和开始菜单快捷方式全部清掉
（这轮把这段固化成 `run-e2e2.ps1 -WithUninstall`，5 项断言全过）。

用户看到的"卸不掉"来自两个残留：

- 这台机器上还装着**原版**：HKLM `Uninstall\eba4c7df-8d63-5e59-8910-62162d2561d2`，
  DisplayName「混剪矩阵智能体」，`UninstallString` 指向 `D:\videomix\Uninstall videomix.exe /allusers`，
  `D:\videomix` 目录也还在。控制面板里两条并排，很容易点错那条。
- 原版（以及我们的旧版）留在桌面/开始菜单的快捷方式指向旧目录，图标自然也是旧图标。

这轮在 `VideoMix.cs` 里补的东西：

- **开始菜单多一个卸载入口**：`卸载 极速VideoMix.lnk`，直接指向 launcher 的 `/uninstall`。
  原来只有一条 `VideoMix.lnk`，想卸载只能靠"程序和功能"。
- **`QuietUninstallString`**（`VideoMix.exe /uninstall /S`）+ `InstallDate` / `EstimatedSize`，
  控制面板和很多"软件管家"类工具默认读这一项。
- **`DisplayIcon` 改成指向 launcher 自己**（图标在编译时用 `/win32icon` 打进去了），
  快捷方式的 `IconLocation` 也改成 launcher —— 这样即使 `uninstallerIcon.ico` 被误删，
  图标也跟着 exe 走，不会变成系统默认图标。
- **装之前清旧快捷方式**：桌面 + 开始菜单（含子目录）里名字像本产品/原版产品、
  但目标不在本次安装目录的 `.lnk` 一律删掉。目标读不出来的（lnk 损坏、COM 失败）**不删**，宁肯留一个。

  命中品牌名且安装目录不是本次目标，就在向导里问一句"是否现在卸载旧版本"，
  选「是」才调它自己的卸载程序（`QuietUninstallString` 优先），选「否」照常继续装。
  **不认识的卸载程序一律不代跑**。

### 9.4 "图标还是旧的"的真因：包里的图标是新的，缓存/旧快捷方式才是旧的

`uninstallerIcon.ico` 是深蓝旋涡，肉眼可分。

所以这轮做的是"让系统重新读一遍"，而不是换图：

- 装完、卸完都调一次 `ShellRefresh.Run()`：`SHChangeNotify(SHCNE_ASSOCCHANGED)` + `ie4uinit.exe -show`，
  让资源管理器把图标缓存和"程序和功能"重读。

  那是原版 Electron 自带的卸载器，图标还是旧旋涡，而新客户端一处都没引用它

### 9.9 v10：账号档案的白底和页头留白

客户截图里「档案记录」右侧那一片原来是**灰的** —— 编辑器不是白卡片了。

根因不在这一块，而是在页头。`.page-shell__title` 同时被两条规则命中：

```css
/* 13.2 页头：要 26px 下边距 + 24px 左右内边距 */
html[data-vm-theme] :is(.page-shell__title, .workbench-page__head) {
  margin: 0 -24px 26px !important;  padding: 15px 24px 13px !important; … }
/* 紧接着的"标题文字"规则，优先级一样、却排在后面 */
html[data-vm-theme] :is(.page-shell__title, .workbench-page__title) {
  margin: 0 !important;  padding: 0 !important; … }
```

两条优先级相同，后写的赢，于是页头那 26px 下边距被清零 ——
**所有用 `.page-shell__title` 的页面，页头底下都是直接贴着内容的**；
只有工作台看着正常，因为它的页头是 `.workbench-page__head`、标题在里层，不吃这条规则。
现在把 `margin/padding` 归零那段只留给 `.workbench-page__title`，页头恢复 26px。

`.account-page__editor` 在 13.3 里本来就在"统一卡片"名单里，但 v5 重排时又被
`html[data-vm-theme] .account-page__editor { border: 0; background: transparent }`
覆盖成了透明 —— 页面底色直接透上来。现在它恢复成正常的白卡片
（`margin-left: 22px` 留出和列表栏的间距、`padding: 18px 20px 20px`），同时顺手清掉三处多余的线：

- 左栏那条竖分隔线（`.account-page__profiles` 的 `border-right`）—— 编辑器已经是卡片，两条线挨着显脏；
- 标题「人设信息填写」自带的横线（`.account-page__title` 的 `border-bottom`）；
- 「档案名称」上面那条压着说明文字的横线（`.account-page__name-row` 的 `border-top`）。

卡片里的「当前改写参考」预览盒也从白底改成 `var(--vm-bg)` 的凹陷面板，白底套白底看不出层次。
