## 一、授权服务器（你自己保存，不要发给客户）

把 `VideoMix-LicenseServer.exe` 放在**一个可写的目录**里（例如 `D:\VideoMix-Server`），
不要放进 `Program Files`，因为它要在自己旁边读写 `license-data.json` 和 `license-server.config.json`。
双击运行，界面上的操作：

1. **监听端口**：默认 `8082`，点“启动服务”后开始监听，界面会列出本机可用地址。
2. **新建授权码**：填写“有效期（天）”“可绑定设备数”“备注”，点“生成”，
   得到形如 `XXXXX-XXXXX-XXXXX-XXXXX` 的激活码，用“复制授权码”发给客户。
3. **查看设备**：查看该激活码已经绑定了哪些设备指纹，可选中后“解绑选中设备”
   （客户换电脑时用这个，解绑后原电脑下次复核就会失效）。
4. **吊销/恢复**：临时让某个激活码失效（客户端 2 分钟内复核到会提示授权失效），
   需要时可以再恢复。
5. **删除授权码**：彻底删除，不可恢复；删除前请确认不再需要。
6. **打开数据目录**：`license-data.json` 就是全部授权数据，**请定期备份这个文件**。
7. **复制签名公钥**：把公钥发给客户端打包用（见下面“六、授权签名”）。

桌面版后台同样会给每个成功的激活结果签名，密钥文件 `license-signing-key.xml` 就在 exe 旁边，
首次启动自动生成；界面上会显示“授权签名指纹”。**这个文件和 `license-data.json` 一起备份**，
换机器时把它一起拷过去，老安装包才能继续激活。

服务器必须在客户端**网络可达**：客户机在同一台电脑、或同局域网、或公网服务器都行，
公网记得放行对应端口。服务器地址不用告诉客户：它已经编译进安装包，
客户装完直接激活即可，换服务器也在后台集中改（见下面“五、换服务器”）。

也可以用命令行指定端口启动：

```powershell
VideoMix-LicenseServer.exe --port=8082
```

## 二、装到客户机上

1. 把 `JSVideoMix-Setup-1.0.0.exe` 拷到客户机，双击运行。
2. 安装界面**只有“安装目录”和两个勾选项**：地址内置在安装包里，界面不显示、客户也不用填。
   选一下安装目录，勾选是否创建桌面快捷方式、安装完成后是否立即启动，点“开始安装”即可。
   （只有你在安装包旁边额外放了 `授权地址.txt` 时，界面才会多出“授权服务器”一行供临时覆盖。）
3. 安装完成后，桌面出现 `VideoMix` 快捷方式，从快捷方式启动。

客户端的完整流程与约定的行为一致：

安装 → 首次启动显示“设备激活”（页面上方是本机设备 ID）→ 客户输入你发放的激活码 →
客户端把激活码 + 本机设备指纹上报给你的授权服务器 → 服务器校验激活码是否存在、
是否在有效期内、是否已吊销、绑定设备数是否超限 → 校验通过后用私钥给这次结果签名 →
客户端验签通过才认为激活成功，把授权缓存在本机 →
之后正常使用，客户端每 2 分钟向服务器复核一次有效期与设备绑定状态。

**再次启动**（与原版行为一致）：退出后重新打开，还是停在“设备激活”页，
激活码已经自动填好，点一下“登录”才进主界面，不用重新输入。
激活页拿激活码的顺序是：先同步问本机代理 `GET http://127.0.0.1:8081/vm/license`
（代理手里是安装目录里的授权票据，激活成功那一刻同步写的），问不到才读本地存储。
以代理为准，是因为 Chromium 的 `localStorage` 是攒一批才落盘（激活完立刻关软件
可能还没写进去），而且本地存储里可能还留着更早一次激活的旧码。

**授权失效时**（被吊销、过期、换电脑）：激活页照常弹出，输入框里的激活码**不会清空**，
启动时也不弹提示；只有点了“登录”才去问服务器，然后弹对应提示——
`激活码已回收` / `激活码已过期` / `设备码不匹配，请重新登录`。

**混剪时某个镜头没人声**（素材 10 秒、文案只有几秒，而这一镜又没生成出配音）：
以前这种镜头会把整段素材播完，成片后段就成了没人说话的“空档”。现在合成前会弹一次
「合成前提醒」，把这些镜头列出来（例如“镜头 1（约 5.1 秒）”）并写明判定口径
（单段无声超过 0.5 秒）：点“取消，我先去改”就不合成（任务变成“已取消”，
补完配音回来点“重试合成”），点“继续合成”则画面按文案长度裁短、不再播完整段素材。
效果见 `截图\16-空档-合成前提醒.png` ~ `截图\18-空档-没配音镜头按文案裁短-合成完成.png`。

**账号档案不会写**：打开「账号档案」，里面已经躺着一份写满的示例档案
（北京烤鸭店的李逍遥：2007 年开店、投了 100 多万、2012 年扩张亏过钱……），

点「生成档案」一次把整份档案写好——称呼、籍贯、投了多少钱、干了多少年、遇到过什么挫折、

## 三、端口与地址约定

| 端口 | 位置 | 说明 |
| --- | --- | --- |
| `8081` | 客户机本机 | 客户端自带的授权代理，只监听 `127.0.0.1`，把软件的激活请求转发给你的服务器。**如果这个端口被别的程序占用，激活会失败** |
| `8082` | 你的授权服务器 | 授权后台的默认端口，可以改 |

客户机上的服务器地址保存在安装目录的 `license-server.json`：

```json
{"serverUrl":"http://192.168.1.10:8082"}
```

地址写错或为空时，启动会弹窗要求重新填写。

**这个 `8081` 不是“给客户看的服务器地址”，也不是用来藏地址。** 软件本体只认本机
`http://127.0.0.1:8081`，真正连哪台服务器由本机代理决定；代理用哪个地址来自安装目录的
`license-server.json`，而后台改地址后这个文件会自动更新。好处是：以后换服务器、迁机房，
已经发出去的安装包不用重装、也不用让客户改配置，后台改一次客户端自己跟过来。
地址本身并不保密（客户机上的东西藏不住），保密靠的是服务端对激活码、有效期、设备数的真实校验。

安装界面上不会出现“授权服务器”这一行，客户只看到“安装目录”和两个勾选项，
截图见 `截图\5-安装界面-不显示授权地址.png`；只有你在安装包旁边放了 `授权地址.txt`
做临时覆盖时，界面才会显示该行，见 `截图\5b-安装界面-有覆盖文件时显示地址.png`。

## 四、换服务器（不用重装客户端）

安装包里内置了一个默认授权地址，客户端每次启动时会顺便问一次当前服务器：
“现在的授权地址是哪一个？”。所以要在后台的**设置 → 客户端授权地址**里改成新地址，
已经装好的客户端就会自动切过去，并把新地址写进自己的 `license-server.json`
（同时记一行 `license-client.log`）。

时间节奏：启动后 15 秒第一次询问，之后 10 分钟内每分钟一次，之后每 5 分钟一次。
切换前会先探一下新地址的 `/health`，新地址不通就不会切，避免把客户带沟里。

要注意两点：

- **旧地址必须还活着**，客户端得先问到新地址才能过去。所以换服务器要留一段过渡期，
  等旧后台的“设置 → 客户端授权地址”里显示“还在用旧地址”的机器归零（或者不再变化）再下线旧地址。
- 更稳的做法是一开始就用**域名**做授权地址。以后换服务器只改 DNS 解析，
  客户端完全无感，也不用动后台设置。

### 内置地址怎么改

内置地址写在 `work\videomix-rebuild\default-server.txt` 里（一行地址）。改完重新运行：

```powershell
powershell -File work\videomix-rebuild\build-launcher.ps1 -PackInstaller
```

就会重新生成 `outputs\videomix-rebuild\JSVideoMix-Setup-1.0.0.exe`（约 972 MB，1~2 分钟）。
不想重新打包，也可以按上面说的用 `授权地址.txt` 放在安装包旁边临时指定。

## 五、授权签名（挡住假冒服务器）

客户端的激活请求由你自己签发的票据兜底：后台每次返回 `SC` 时都会附上一张
RSA-2048 / SHA-256 签名的票据（内容含激活码、设备指纹、签发时间、到期时间），
客户端用**编译进安装包的公钥**验签，验不过就把结果改写成失败，界面提示
「授权校验未通过：签名验证失败（对方不是正版授权后台）」。

所以别人照着接口自己搭一台假服务器返回 `SC`，客户端不会认。三种造假手法
（不签名 / 用别人的私钥 / 指纹对不上）都实测被拒。当前的正式公钥指纹是 `f95b88ffbe6bd54e`。

**发货前必须确认两件事**：

1. `default-server.txt` 里的地址是真实的公网地址（不是 `127.0.0.1`），打包脚本会提示你。
2. `keys\license-public.xml` 和你正式后台那一把私钥是同一对。

```powershell
# 桌面版后台：界面点“复制签名公钥”，存成 keys\license-public.xml（一行）
# 网页版后台：设置 → 授权签名密钥 → 复制公钥，同样存成 keys\license-public.xml
powershell -File work\videomix-rebuild\build-launcher.ps1 -PackInstaller
```

打包脚本会打印“内置授权公钥指纹”。**找不到公钥文件就直接报错拒绝打包**，避免发出一个
等于没验签的安装包。它同时会把新编译的启动器写回 payload 压缩包，
所以装出来的 `VideoMix.exe`（含本机授权代理）和外层启动器是同一份。

换密钥的后果：老安装包里是旧公钥，一旦后台换了私钥，老客户端的激活和复核都会失败。
所以私钥要么一直不动（推荐），要么换的时候同步重新打包、通知客户升级。

需要**生成一把全新的密钥对**时，跑这个脚本（不依赖后台、不联网）：

```powershell
pwsh -NoProfile -File work\videomix-rebuild\new-signing-key.ps1 -OutDir D:\keys
```

它会输出 `license-signing-key.xml`（私钥，丢进后台）和 `license-public.xml`（公钥，覆盖
`keys\license-public.xml` 后重新出包），并打印指纹（例如 `36f651550e4d3246`）。
后台安装页选「我自己粘贴一把私钥」时，粘的就是那个私钥文件里整段 `<RSAKeyValue>…</RSAKeyValue>`。

## 六、发新版本给已经装好的客户（在线升级）

装好的客户端不用你联系、也不用重装：**你在授权后台点一下发布，客户下次联网就自己升级**。

打包机上一共两条命令：

```powershell

# 2) 出给老客户的更新包（只含变化文件，约 15 MB）

```

安装包文件名跟着品牌和版本走：`brand.json` 里写的是 `JSVideoMix-Setup-1.0.0.exe`，
把版本号改成 1.0.1 之后自动变成 `JSVideoMix-Setup-1.0.1.exe`，不用手改脚本。

第 2 步产出 `outputs\videomix-rebuild\update-client-1.0.1.zip`，默认只装这两个文件：
`VideoMix.exe`（启动器，含本机授权代理）和 `videomix\resources\app.asar`（界面与主进程代码）。

> 为什么两个文件就够了：界面代码全在 `app.asar` 里，启动器只管安装/授权代理/升级。
> Electron 主程序 `videomix\videomix.exe` 有 222 MB，里面唯一需要跟着 asar 变的是
> **asar 完整性哈希**——启动器在拉起主程序之前会自己把这个哈希对齐
> （日志里写“已同步 app.asar 完整性哈希”），所以不必把 222 MB 重新发一遍。

然后到授权后台左侧「客户端升级」：填同样的版本号、选这个 zip、上传 → 写更新说明 → **发布更新**。

**先用安装包内置公钥验签、再算 SHA256**，两项都通过才会落地、重启时替换。
默认会弹窗问客户「现在更新吗」，后台勾「强制更新」就不问直接升；

后台那一页能看到**每台机器的版本分布**（「还没升级 N 台」），撤回、删除都在同一个页面。
细节和注意事项见 `outputs\videomix-web\README.md` 第七章。

## 七、注意事项

- 客户端**必须从桌面快捷方式（或安装目录里的 `VideoMix.exe`）启动**。
  直接运行 `videomix\videomix.exe` 不会启动本机授权代理，激活会失败。
- 两个 EXE 都**没有代码签名**，Windows Defender / SmartScreen 可能拦截或报毒，
  部署前先在客户机上放行/加白名单，或者自己买证书做签名。
- 软件自带更新已经被关闭，客户端不会被厂商的更新覆盖回旧版本；
  以后升级客户端走**你自己后台的在线升级**（见上一章），改动特别大时也可以直接发新安装包。
- 客户端的激活校验只走你的服务器，接口是 `/rpc/authActivateCode`（激活）和
  `/rpc/judgeActivateCode`（周期性复核），返回 `SC` 表示通过，
  `E1` 激活码不存在、`E2` 设备不匹配或超出绑定数、`E3` 已过期、`E4` 已吊销、
  `E9` 授权校验未通过（签名验不过：连到了假服务器，或后台换了密钥而安装包还是旧公钥）。
- 验签失败的细节记在客户机安装目录的 `license-client.log`，成功签发的票据缓存在
  `license-ticket.json`，排查问题时看这两个文件。
