# 换授权密钥操作手册（私钥 / 公钥 / 指纹）

## 一、这三个东西是什么关系

一套非对称密钥就是一把私钥 + 一把公钥，两者数学上配对，由私钥算出公钥，反过来算不回去。

私钥（`license-signing-key.xml`）放在后台，用来给激活结果盖章。谁拿到它，谁就能伪造激活票据，所以它只能在你自己的服务器上。

公钥（`license-public.xml`）编进客户端安装包。客户端每次激活，都拿它去验证后台盖的章是不是真的，验不过就报 `E9`。

指纹（例如 `f95b88ffbe6bd54e`）不是第三把钥匙，它只是这把钥匙的身份证号：把公钥的 `Modulus` 去掉前导零、做一次 SHA-256、取前 8 个字节的十六进制。它有两个用处：一是让你在界面上核对后台和客户端用的是不是同一把，二是票据里会带上它，客户端发现对不上直接拒绝。

所以换钥匙其实是三件事一起变：后台的私钥文件、打包目录里的公钥文件、以及界面上显示的那个指纹。三者同源，改一个就必须改全部。

## 二、钥匙分别躺在哪里

| 位置 | 文件 | 谁用 |
| --- | --- | --- |
| 客户端打包目录 | `work\videomix-rebuild\keys\license-private.xml` | 打包时的备份，也是旧后台留下的那份 |
| 客户端打包目录 | `work\videomix-rebuild\keys\license-public.xml` | **打包脚本读它**，编进启动器 |
| PHP 后台部署包 | `outputs\videomix-php\keys\license-private.xml` | 安装时选「用程序里自带的那把」就导入它 |
| PHP 后台数据库 | `settings` 表的 `signing_key_xml` | 后台真正在用的私钥，装完之后改这里 |
| 客户端 exe 内部 | 编译进 `VideoMix.exe` 的字符串 | 客户端验签用 |

要注意的是：后台装好之后，真正生效的私钥是**数据库里那条记录**，不是磁盘上那个文件。磁盘上的文件只在「第一次安装」那一刻被读进来。所以已经装好的后台想换钥匙，要在后台界面「设置 → 授权签名」里换，光替换文件没用。

## 三、什么时候需要换

私钥泄露了，或者你想换成自己生成的钥匙，就需要换。除此之外不建议动：换一次，所有已经发出去的客户端都要重装，因为老安装包里是旧公钥。

## 四、换钥匙的完整步骤

### 第 1 步：生成新钥匙对

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "E:\GPT Codex\2026-09-15\new-chat\work\videomix-rebuild\new-signing-key.ps1" -OutDir "D:\keys"
```

产出 `D:\keys\license-signing-key.xml`（私钥）和 `D:\keys\license-public.xml`（公钥），并打印指纹。命令里 `-ExecutionPolicy Bypass` 是必须的，Windows 默认禁止运行脚本。

### 第 2 步：核对新旧指纹

```powershell
& "E:\GPT Codex\2026-09-15\new-chat\work\tools\php\php.exe" -r "require 'E:/GPT Codex/2026-09-15/new-chat/outputs/videomix-php/lib/Crypto.php'; foreach (array_slice($argv,1) as $p) { $k = new SigningKey(parse_key_xml(trim(file_get_contents($p)))); printf(\"%-50s %s\n\", $p, $k->kid); }" "D:\keys\license-signing-key.xml" "E:\GPT Codex\2026-09-15\new-chat\work\videomix-rebuild\keys\license-private.xml"
```

看两个指纹是不是你想的那样。这一步只是确认，不改任何东西。

### 第 3 步：把新钥匙铺到三个地方

```powershell
$new = "D:\keys"
$repo = "E:\GPT Codex\2026-09-15\new-chat"
Copy-Item "$new\license-signing-key.xml" "$repo\work\videomix-rebuild\keys\license-private.xml" -Force
Copy-Item "$new\license-public.xml"      "$repo\work\videomix-rebuild\keys\license-public.xml"  -Force
Copy-Item "$new\license-signing-key.xml" "$repo\outputs\videomix-php\keys\license-private.xml"   -Force
```

### 第 4 步：验证票据链路通

```powershell
cd "E:\GPT Codex\2026-09-15\new-chat"
& "work\tools\php\php.exe" work\php-test\make-ticket.php "outputs\videomix-php\keys\license-private.xml" > work\php-test\out.json
python -X utf8 work\php-test\verify-ticket.py work\php-test\out.json
```

最后一行要是 `ALL OK`。它会打印后台指纹，并检查票据是用这把钥匙签的、能验过。

### 第 5 步：重新出安装包

因为公钥换了，老安装包作废，必须重出：

```powershell
cd "E:\GPT Codex\2026-09-15\new-chat\work\rebrand"
python rebrand.py
cd "E:\GPT Codex\2026-09-15\new-chat\work\videomix-rebuild"
powershell -NoProfile -ExecutionPolicy Bypass -File ".\build-client-update.ps1" -Version 1.0.2
```

打包过程中会打印 `内置授权公钥指纹：xxxxxxxx`。这个值必须等于第 1 步打印的指纹，不等就是没换成功。

### 第 6 步：确认安装包里真的是新公钥

把 exe 里那段 `<RSAKeyValue>` 抠出来算一遍指纹：

```powershell
python -c "import re,base64,hashlib; b=open(r'E:\GPT Codex\2026-09-15\new-chat\outputs\videomix-rebuild\JSVideoMix-Setup-1.0.2.exe','rb').read(2000000); m=re.search(rb'<\x00R\x00S\x00A\x00K\x00e\x00y\x00V\x00a\x00l\x00u\x00e\x00>',b); t=b[m.start():m.start()+4000].decode('utf-16-le','ignore'); x=t[:t.index('</RSAKeyValue>')+15]; mod=base64.b64decode(re.search(r'<Modulus>([^<]+)</Modulus>',x).group(1)); print(hashlib.sha256(mod).hexdigest()[:16])"
```

打印出来的指纹要和第 1 步一致。

### 第 7 步：已经装好的后台怎么换

如果后台已经装过、库里已经有数据，光换文件不够，要去后台界面 **设置 → 授权签名**，把 `D:\keys\license-signing-key.xml` 里整段 `<RSAKeyValue>…</RSAKeyValue>` 粘进去保存。保存之后界面上显示的指纹应该变成新的。

同理，全新安装的时候，安装页第 3 步「授权签名私钥」选「我自己粘贴一把私钥」，粘进同一段内容，也可以。

## 五、回滚

换错了就换回去：把旧的两份文件复制回第 3 步那三个位置，重新跑第 5 步出包，后台再按第 7 步粘回旧私钥。旧钥匙存在
`outputs\备份\密钥-旧-29566eb98cee5506-20260920\`。
