# 自动化流程事件

企业主管理在侧边栏「自动化功能」维护事件。中文脚本从上往下执行；左侧事件按显示顺序全部执行。后面的执行者设置覆盖前面的设置，项目参与者累加。单条事件出错会撤销该事件的修改，记录失败并继续后续事件。

升级后自动迁移三条可关闭的默认事件：独立任务、子任务创建时分配给创建人，以及项目根任务节点变更记录。手工指定执行者时默认事件不覆盖；其他自定义事件仍可覆盖。项目根任务默认不分配。分配动作会保留正式任务履历。

## 示例

先在「人员集合」中从企业成员选择工程师，保存为「报价工程师」。随后新建事件：

```text
当 项目根任务 状态变化时
如果 当前任务的原状态 等于 「询盘发布」
并且 当前任务的状态 等于 「内部报价」
  将 当前任务的执行者 设为 从 集合「报价工程师」 随机选择一人
  添加 创建人 为 当前任务的参与者
否则
  记录 「此次变更不需要报价分配」
结束判断
```

支持嵌套判断、并且、或者（并且优先），以及创建人的姓名、账号、岗位条件。成员重名时使用唯一账号；人员集合无有效成员时记录失败。参与者动作当前作用于项目任务的项目成员。

脚本不是任意代码：语句注册表、编译器和受控执行器共同定义可用能力，未知语句报出行号，不会通过 eval 执行。暂不支持变量、循环或任意外部调用。

## AI 编辑配置

服务端设置以下环境变量后重启服务：

- `AUTOMATION_AI_BASE_URL`：兼容 Chat Completions 的接口基础地址（包含供应商要求的 `/v1` 等路径）。
- `AUTOMATION_AI_API_KEY`：接口密钥，仅服务端使用。
- `AUTOMATION_AI_MODEL`：模型名称。

点击底部发送按钮，会向配置的服务发送需求、当前脚本、当前企业成员的显示名称/账号/岗位及集合名称。请使用企业批准的模型服务。返回脚本经过语法与成员引用校验，先展示草稿，点击「应用到编辑器」后仍需保存才生效。未配置时明确提示，不使用模拟 AI 响应。

修改同一事件采用版本校验，旧版本不能覆盖新版本。正式业务数据不会由 AI 自动发送或执行。
