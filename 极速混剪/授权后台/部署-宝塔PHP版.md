# VideoMix 授权中心 · 宝塔 + PHP + MySQL 部署手册

这套后台是**纯 PHP 网站**：代码放宝塔站点目录，数据全在 MySQL 里，
不依赖 Python、不依赖 SQLite、不需要长期开着自己电脑的什么程序。
装完之后你在任何电脑浏览器打开域名都能管激活码。

---

## 0. 一句话流程

```
上传代码 → 建站点(PHP) → 建数据库 → 网站目录指向 public → 调上传限制
        → 打开 /install.php 填数据库和总账号 → 登录后台 → 绑域名开 HTTPS
```

全程大概 10 分钟。

### 0.1 最少要动几处宝塔？答案是四处（其中一处就粘一行字）

1. **新建站点**（选 PHP，版本 7.4 ~ 8.3 都行）
2. **新建数据库**（宝塔面板里点一下，记下用户名/密码）
3. **网站目录的「运行目录」改成 `/public`**（第 4 节）
4. **伪静态框里粘一行**（第 5 节，复制粘贴，不用理解）

就这四处。**不用改「配置文件」、不用动那两段 `location ~ .*\.(js|css)$`、
不用放行额外端口。** 部署包里已经把网页文件放在 nginx 和 PHP 都能找到的位置了。

唯一可能还要加一行 `client_max_body_size 512m;` 的情况是：你要用
「客户端升级」上传 16 MB 左右的更新包（第 6 节）。不发布更新的话完全不用管。

> 之前那版部署包要求把 `location` 正则那两段也改掉，是因为那时候网页文件只放在
> `public/web/`，nginx 自带的 `.js/.css` 规则会抢在 PHP 前面去磁盘找文件、然后 404。
> 2026-09-20 12:24 之后的部署包已经修掉了，不再需要动那两段（详见第 5.1 节）。

## 1. 上传代码

把整个 `videomix-php` 目录传到服务器，建议放在：

```
/www/wwwroot/videomix-license
```

宝塔操作：**文件 → 进入 /www/wwwroot → 新建目录 videomix-license → 上传 zip → 右键解压**。

解压后目录结构应该是这样（关键几个）：

```
videomix-license/
├── public/          ← 网站根目录要指到这里
│   ├── index.php    接口入口
│   ├── install.php  安装向导
│   └── web/         后台网页（PC + 手机H5）
├── lib/             PHP 源码
├── sql/schema.sql   建表脚本
├── keys/license-private.xml   授权签名私钥（别外传）
├── data/updates/    客户端更新包存放目录
├── data/backups/    数据库备份存放目录（后台「数据备份」写这里）
└── config.sample.php
```

> ⚠️ `keys/license-private.xml` 是整套授权的命根子。
> 谁拿到它谁就能签出"正版"票据。不要放到网盘、不要发给客户、不要提交到公开仓库。

## 2. 新建站点

宝塔 → **网站 → 添加站点**：

| 项目 | 填什么 |
| --- | --- |
| 域名 | 你的域名，比如 `license.abc.com`（没域名就先填服务器 IP） |
| 根目录 | `/www/wwwroot/videomix-license` |
| FTP | 不创建 |
| 数据库 | **选 MySQL**（下一步会用到，也可以这里一起建） |
| PHP版本 | **8.0 / 8.1 / 8.2 / 8.3 都行**；PHP 7.4 也能跑 |

建完站点后，**先去「软件商店 → PHP-x.x → 安装扩展」确认这两项是装好的**：

- `pdo_mysql`（必装，连数据库用）
- `openssl`（必装，签授权票据用）

宝塔的 PHP 默认都带，如果没开就在"安装扩展"里点一下。

## 3. 新建数据库

宝塔 → **数据库 → 添加数据库**：

| 项目 | 建议 |
| --- | --- |
| 数据库名 | `videomix_license` |
| 用户名 | `videomix_license` |
| 密码 | 点"随机"生成，**记下来** |
| 权限 | 本地服务器 |
| 编码 | utf8mb4 |

点提交，宝塔会把库建好。**不需要手动导入任何 SQL**——
下一步的安装向导会自动建表。

（如果你更喜欢手动：把 `sql/schema.sql` 丢进 phpMyAdmin 导入也一样。）

## 4. ★ 把网站根目录改成 public

这一步最容易漏，漏了会 404 或者把私钥暴露出去。

宝塔 → **网站 → 你的站点 → 设置 → 网站目录**：

```
把「运行目录」改成： /public
```

保存。这样 `https://你的域名/` 实际指向的是 `public/index.php`，
而 `keys/`、`lib/`、`data/` 都在网站根目录之外，浏览器访问不到。

---

## 5. 设置伪静态（nginx 站点）

宝塔 → **网站 → 你的站点 → 设置 → 伪静态**，把内容清空后粘贴：

```nginx
location / {
    try_files $uri $uri/ /index.php?$query_string;
}
```

保存。这一步让 `/api/...`、`/rpc/...`、`/health` 这些没有实体文件的地址也能正常访问。

> 如果你的站点是 **Apache**：不用配伪静态，项目里已经带了 `public/.htaccess`，
> 只要确认 Apache 开了 `mod_rewrite` 就行（宝塔默认开）。

### 5.1 后台白屏、`/app.css` `/app.js` 404 怎么来的

宝塔给新站点生成的配置文件里，自带两段"静态资源直接给"的规则：

```nginx
location ~ .*\.(gif|jpg|jpeg|png|bmp|swf)$ { expires 30d; ... }
location ~ .*\.(js|css)?$                    { expires 12h; ... }
```

nginx 里正则 `location` 的优先级比 `location /` 高，所以 `/app.js`、`/app.css`
不会走伪静态交给 PHP，而是被 nginx 直接当成磁盘文件去网站根目录找。
**部署包 2026-09-20 12:24 之后的版本**已经把这些网页文件按 nginx 能找到的路径放好了
（网页里引用的是 `web/app.css`、`web/app.js`），所以上面两段规则留着也没关系，
**不需要改任何 nginx 配置**。

如果你用的是**更早的部署包**、后台白屏、浏览器 F12 里看到 `/app.css` 或 `/app.js` 404，
有两个一分钟就能解决的办法，任选一个：

**办法一（推荐，直接把这两段删掉）：**

宝塔 → 网站 → 你的站点 → 设置 → **配置文件**，找到上面那两段 `location ~ ...`，
整段删掉（连同它们的花括号），保存。

**办法二（保留这两段，各加一行让找不到就转给 PHP）：**

```nginx
location ~ .*\.(gif|jpg|jpeg|png|bmp|swf)$ {
    expires      30d;
    error_log /dev/null;
    access_log /dev/null;
    try_files $uri /index.php?$query_string;   # ← 加这一行
}

location ~ .*\.(js|css)?$ {
    expires      12h;
    error_log /dev/null;
    access_log /dev/null;
    try_files $uri /index.php?$query_string;   # ← 加这一行
}
```

改完保存（宝塔会自动 `nginx -t` + reload）。验证：浏览器打开
`https://你的域名/app.css`，能看到一大段 CSS 就是好了；再看
`https://你的域名/pc.html` 是否正常显示登录页。

> 判断用哪个办法：只有**老的部署包**才需要做这一步。用新包重新覆盖一次
> `public/web/` 目录（或整包重传），这一步就可以跳过。

## 6. 调大上传限制（要发客户端更新包才需要）

宝塔 → **网站 → 你的站点 → 设置 → 配置文件**，
在 `server {` 里面加一行（或改掉已有的）：

```nginx
client_max_body_size 512m;
```

再改 PHP 的上传上限：宝塔 → **软件商店 → PHP-x.x → 设置 → 配置修改**：

```ini
upload_max_filesize = 512M
post_max_size = 512M
max_execution_time = 600
max_input_time = 600
```

保存后**重载 PHP**（宝塔会提示）。

不打算用"在线升级"功能的话，这一步可以跳过。

## 7. 打开安装向导

浏览器访问：

```
https://你的域名/install.php
```

最上面先选「安装方式」：

- **新建安装**（默认）：全新部署，走下面的 1~3
- **用备份文件恢复**：搬迁/还原用，只填数据库 + 上传旧后台导出的 `.sql`，
  账号密码沿用备份里的（详见第 11 节）

新建安装填三块内容：

1. **数据库**：地址 `127.0.0.1`、端口 `3306`、库名 / 用户名 / 密码（第 3 步记的）
2. **总账号**：你自己的登录账号和密码（≥6 位）
3. **授权签名私钥**：默认选"用程序里自带的那把"，保持不动

点「开始安装」。成功后会显示一个**授权签名指纹**，
正常情况下是：

```
f95b88ffbe6bd54e
```

不是这个值就说明密钥换掉了，之前发出去的安装包会激活失败——先停下来确认。

装完访问 `/` 用刚填的账号登录。

> 安装完成后可以删掉 `public/install.php`，防止被人重装。

## 8. 域名 + HTTPS

宝塔 → 网站 → 设置 → **SSL** → Let's Encrypt → 勾选域名 → 申请。
成功后打开 **强制 HTTPS**。

然后在后台 **设置 → 客户端授权地址** 里填你的地址（**不要带路径、不要带斜杠**）：

```
https://license.abc.com
```

保存之后，所有已经装好的客户端下次启动会自动从这里拿到新地址，
以后换服务器只需要在这一处改地址，不用重新发安装包。

---

## 9. 客户端的授权服务器地址从哪来

客户端安装包出厂时内置了一个默认地址。上线后按这个顺序确认：

1. 后台 **设置 → 客户端授权地址** = 你的正式域名
2. 安装包里内置的默认地址 = 同一个域名

这样新客户装完就能直接激活，老客户也会自动跟着后台的地址走。

自检：浏览器打开 `https://你的域名/health`，应该返回

```json
{"service":"videomix-license","ok":true,"version":"2.4.0","time":"..."}
```

## 10. 日常使用

| 想做什么 | 去哪 |
| --- | --- |
| 生成激活码 | 批次管理 → 新建批次（1~5000 个） |
| 把码给代理商 | 激活码列表勾选 → 分配给代理商；或整批分配 |
| 开一级代理 | 代理商管理 → 新建（总账号建的就是一级） |
| 一级代理开二级 | 代理商登录后同样在代理商管理里新建 |
| 看谁绑了哪台机器 | 激活记录 / 激活码详情 → 绑定设备 |
| 客户换电脑 | 激活码详情 → 解绑旧设备，客户端就能在新机器激活 |
| 吊销某个码 | 激活码列表 → 吊销 |
| 发新版本 | 设置 → 客户端升级 → 上传 zip → 发布 |
| 备份整库 / 换服务器 | 数据备份 → 立即备份 → 下载（见第 11 节） |

权限规则：总账号看全部；一级代理看自己 + 自己开的二级；
二级代理只能看自己名下的激活码。一二级代理用的是同一个后台页面。

## 11. 备份与迁移

后台自带备份，不用碰命令行。整个过程和 DedeCMS 那种后台备份一样：
**后台点一下 → 下载文件 → 新服务器访问 `/install.php` 选「用备份文件恢复」**。

### 备份（在后台里点）

登录后台 → 左侧 **数据备份**：

| 按钮 | 作用 |
| --- | --- |
| 立即备份 | 把整个库（激活码、批次、代理商、绑定设备、日志、设置、签名私钥）导成 `data/backups/videomix-backup-日期时间.sql` |
| 下载 | 把备份存到本地（换机器时一定要下载走） |
| 恢复 | 把这个备份导回**当前**数据库，覆盖现有数据（系统会先自动另存一份当前数据） |
| 删除 | 删掉服务器上的备份文件 |

备份是纯 SQL 文本，出问题可以自己打开看。
`data/backups/` 目录需要写权限（宝塔里 755、属主 `www`），`/check.php` 会替你检查。

> ⚠️ 备份文件里含**全部激活码 + 代理商账号 + 授权签名私钥**，等于整套授权的命根子。
> 只在自己可控的机器之间传，别发网盘、别发客户。
> 私钥另外建议离线存一份 `keys/license-private.xml`。

### 迁移到新服务器（换机器）

1. 旧服务器后台 **数据备份 → 立即备份 → 下载**，拿到 `videomix-backup-xxx.sql`
2. 新服务器按第 1~5 步把代码传上去、建好站点，再建一个**空的** MySQL 库
3. 浏览器访问 `https://新域名/install.php`，「安装方式」选 **用备份文件恢复**
4. 填数据库连接（第 2 步建的空库）→ 上传那个 `.sql` → 点「开始恢复」
5. 恢复完成页面会显示**授权签名指纹**，正常还是 `f95b88ffbe6bd54e`；然后用**原来后台的账号密码**登录
6. 后台 **设置 → 客户端授权地址** 改成新域名（含第 8 步的域名 + HTTPS）

恢复模式下**不需要**填总账号密码、**不会**换签名私钥——账号、密码、激活码、代理商全部来自备份。
老客户端不用重装，等它们下次联网拿到新地址就自动跟过去。

顺手把 `data/updates/`（已发布的客户端更新包）和 `config.php` 也复制过去，
新服务器就不用重新上传更新包。

### 迁移前自查

- `https://新域名/check.php` 是否全绿（尤其 `data/backups` 可写、openssl 已开）
- 恢复后 `/api/codes` 里的激活码数量、`指纹` 是否和旧站一致
- 备份文件上传上限不够（提示 413 或传不完）时，按第 6 步把
  `upload_max_filesize` / `post_max_size` 调到 512M 再重载 PHP

## 12. 发布新版本 & 客户端怎么更新

1. 本地把客户端做成一个 zip（更新器支持**全量和个别文件**，
   按客户端的更新包格式打包即可；不确定就整包全量，最稳）
2. 后台 → **设置 → 客户端升级** → 填版本号（如 `1.0.1`）→ 选 zip → 上传
3. 填更新说明，需要强制就勾"强制更新" → 点 **发布**
4. 客户端启动时会自己来问 `/api/client-version`，
   有新版就下载、验签、校验 sha256，然后替换文件

"设置 → 客户端升级"页面下方能看到**哪些设备还停在旧版本**，方便你确认铺开了没有。
不想推了就点「撤回」，客户端立刻收不到这次更新。

## 13. 常见问题

**Q：打开域名显示"授权后台启动失败"？**
数据库连不上。回到 `/install.php?setup=1` 重新填数据库信息。

**Q：客户端激活提示"服务器签名密钥异常"（E9）？**
PHP 没开 `openssl` 扩展。宝塔 → PHP 设置 → 安装扩展 → 装 openssl → 重载。

**Q：客户端提示"服务器密钥指纹 xxx 与安装包内置的 f95b88ffbe6bd54e 不一致"？**
后台用了别的私钥。到 设置 → 授权签名 把 `keys/license-private.xml` 的内容贴进去保存，
指纹变回 `f95b88ffbe6bd54e` 即可。

**Q：上传更新包提示 413 / 传不完？**
第 6 步的 `client_max_body_size` 和 `upload_max_filesize` / `post_max_size` 没改，或没重载。

**Q：备份文件太大，恢复时传不完？**
同上，按第 6 步把 `upload_max_filesize` / `post_max_size` 调到 512M。
还是传不完就先在旧服务器上把备份下载下来，用 phpMyAdmin 或命令行导入新库，
再访问 `/install.php` 走一次「新建安装」（不要覆盖表）。

**Q：后台「数据备份」提示目录不可写？**
给 `data/backups` 目录 755、属主 `www`（和第 4 步里的其他目录一样）。

**Q：手机能开吗？**
能。同一个域名，手机浏览器打开会自动进 H5 版；电脑打开进 PC 版。
想手动切：`https://域名/?view=pc` 或 `?view=mobile`。

**Q：之前那套 Python 后台怎么办？**
PHP 版跑通、确认后台数据没问题之后，就可以停掉 Python 进程、
把原来的 systemd 服务停掉删掉（`systemctl stop/disable videomix-license`），
目录可以留着做备份。两边**不要同时对外开同一个域名**，
但客户端只会连你后台里配置的那一个地址，所以切换是平滑的。

## 15. 旧版（Python 后台）怎么彻底删干净

旧版是一台常驻的 Python 程序（systemd 服务 `videomix-license`，端口 `8082`，
目录 `/www/wwwroot/videomix-license`，数据在 `data/license.db` 这个 SQLite 文件里）。
**删之前先做第 1 步把数据搬过来**，不然老客户下次校验会失败。

### 第 1 步：先搬数据（只有「之前发过激活码」才需要）

如果你还没对外发过激活码，**跳过这一步，直接从第 2 步删**。

发过的话，把旧服务器上这个文件下载到本地：

```
/www/wwwroot/videomix-license/data/license.db
```

然后新后台 → **数据备份 → 从旧版导入** → 选中这个 `license.db` → 点「导入 license.db」。就这一步，
不用跑命令、不用转换。后台会自己读旧库，把激活码、代理商、绑定设备搬过来。

导入**只补不覆盖**：账号名重复、激活码重复的自动跳过；总账号密码、签名私钥、
授权地址、现有激活码都不动。新建的代理商账号会拿到随机密码，导入结果里会列出来。

> 旧后台还能打开的话，也可以登录旧后台访问 `你的旧域名/api/export`，
> 把 JSON 存下来用同一个页面的「导入 JSON」入口，效果一样。
>
> 如果这一步提示「没开 pdo_sqlite 扩展」，去宝塔「软件商店 → PHP 设置 → 安装扩展」

### 第 2 步：停掉并删掉 systemd 服务

```bash
systemctl stop videomix-license
systemctl disable videomix-license
rm -f /etc/systemd/system/videomix-license.service
systemctl daemon-reload
systemctl reset-failed videomix-license 2>/dev/null
```

确认服务真的没了：

```bash
systemctl status videomix-license --no-pager     # 应显示 Unit ... could not be found
curl -s http://127.0.0.1:8082/health || echo '8082 已空'
```

### 第 3 步：删掉宝塔里的托管项（如果有）

宝塔 → **网站 → Python 项目**：如果里面有 `videomix-license`，
点**停止**再**删除**（删除时若问「是否删除项目目录」，选**不删除**，我们先停用、后清目录）。
接着宝塔 → **安全 → 放行端口**，把 8082 那条规则删掉；
云服务器控制台的安全组里 8082 也可一并关掉（新后台走 80/443，不再需要 8082）。

### 第 4 步：删掉旧站点和旧代码

如果旧站是宝塔里单独建的站点，先 **网站 → 删除站点**（别勾「删除数据库」以外不需要的选项，
或者干脆保留目录先观察几天）。

确认新后台已经跑稳（至少几天）之后，再删旧目录：

```bash
# 先留一份数据文件到别处，确定不要了再删
cp /www/wwwroot/videomix-license/data/license.db /root/license.db.bak
rm -rf /www/wwwroot/videomix-license
```

### 第 5 步：删掉反向代理和旧域名解析

- 旧站点若做过反向代理到 `127.0.0.1:8082`：站点设置 → 反向代理 → 删除
- 旧域名不再指向这台机器/这个站点：删掉解析，或把域名改指向新站点
- 后台 **设置 → 客户端授权地址** 确认已经改成新域名（客户端只认这里的地址）
